{# ONE TRIGGER FOR AN OPTION CHANGING, AND IT IS `input`. Every control here fires it — text, number, select and checkbox alike, in Chromium and Firefox — so `change` beside it only sent the same readout twice: a checkbox or a select fires both, two debounce timers ran out in the same millisecond, and the second request aborted the first, logging an htmx error on every change (measured, both engines). `queue last` rather than `replace` for the one change that can still overlap a request in flight: `replace` loses track of the request that did the replacing (see CLAUDE.md's note on htmx's request ordering), and a queue never aborts, so the readout always ends on the last options. #}
