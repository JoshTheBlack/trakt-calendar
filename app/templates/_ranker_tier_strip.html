{# WHAT A TIER HOLDS, AS ARTWORK: the little row of posters in its header. ONE RENDERER, TWO WAYS IN — the shell draws it inline with the tier, and `_ranker_tier_strips.html` draws every one of them again out of band. A second copy of this markup is how the strip and the tier would come to disagree about what a tier holds, which is the thing this partial exists to keep from happening. IT IS A VIEW OF THE TIER'S CONTENTS, SO ONLY THE SERVER CAN DRAW IT. A drag, a nudge and the move menu change which titles a tier holds without the server hearing about it until the save lands, so the strip the page was rendered with goes stale. Every action that answers with the board redraws it; the ones that answer with a save ask for the fragment instead. `oob` ADDRESSES IT BY SELECTOR RATHER THAN BY id, because there is one of these per tier and an out-of-band swap needs to reach the right one. The value must contain no space for htmx to read it as a style and a selector; `.ranker-strip[data-tier='…']` has none, and a uid is `[A-Za-z0-9_-]` so it can never close the quote. TEN ARE SHOWN, AND A FEW MORE ARE DRAWN SO THAT STAYS TRUE. Not every title has a poster, and nobody knows which until a browser asks: one that fails takes itself out of the strip (ranker/rows.js, `data-if-missing`), which used to leave the strip one short for every miss among the first few. So the strip draws STRIP_DRAWN pictures and style.css shows only the first ten still standing (`.ranker-strip img:nth-of-type(n+11)`) — when one removes itself, the next moves up into view with nothing measuring anything. The spares are lazy, like every picture here. Only titles WITH a tmdb id are counted, since one without has no picture to ask for and would otherwise use up a place. #} {%- set STRIP_DRAWN = 14 %} {% macro strip(category, oob=False) -%} {%- for item in (category['items'] | selectattr('tmdb') | list)[:STRIP_DRAWN] %} {%- endfor %} {%- endmacro %}
