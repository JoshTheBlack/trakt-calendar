{% import '_toast.html' as toast %} {# THE NETWORK → EMOJI EDITOR'S ROWS, drawn by the server and swapped whole. A FORM HOLDS ITS OWN EDITS, which is the whole reason this is markup. The rows used to be built from an array in the browser, so anything that redrew them — adding a row, removing one, backfilling from the month's networks — first had to read every field back out of the DOM into that array or an unsaved edit vanished. There is no array now: what is on screen is a form, every action posts it, and the answer is the rows the server made of what it was sent. ADDING AND REMOVING A ROW ARE POSTS THAT WRITE NOTHING, and that is the right verb rather than a compromise. The convention this app follows is that an address may carry a REFERENCE and never data — and the data here is a form full of edits nobody has saved, which the server cannot look up. So the form is the body, and the answer is the same rows with one more or one fewer. ONE FIELD PER VALUE, NAMED BY POSITION. `network-0`, `emoji-0`, `network-1`… json-enc serializes a form as flat name/value pairs, and while repeating one name does produce an array, a form with a SINGLE row would then send a string where a form with two sends a list — the ambiguity the calendar's filter chips are named the way they are to avoid. The suffix means nothing but "these two belong together"; routes._emoji_rows_from_form pairs them by it and the answer renumbers from zero. A BLANK ROW IS ALWAYS DRAWN AT THE END, which is what "+ Add network" was for. Typing into it and pressing Add commits it and draws another. THE LOGO IS DRAWN WHERE THERE IS ONE and the row simply has none where there is not. It was an with an `onload` and an `onerror` toggling a class, because only the browser knew whether the tile existed; the tracker's own rows stopped asking the browser that (see _distrakt_rows.html's `badge`) and this follows, with `.has-logo` decided here.
